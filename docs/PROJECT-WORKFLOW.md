# Emberbrook project workflow

## 1. Establish the game design — current focus

Use the working title Emberbrook: The Lost Harvest. Confirm the story, six-area scope, controls, exploration loop, battle commands and ending. Playtest the village introduction and a complete route through the game.

Prioritize clear navigation, responsive movement, readable combat and consistent art. Tune the existing game before adding more systems.

## 2. Discuss the course topic as a group — pending

Review the actual lessons and select one concept everyone can explain. Decide where it will affect a player decision or game outcome. Solve one worked example before committing to implementation.

The previous optimization and inflection-point drafts are options for review only. No topic has been chosen on the group’s behalf.

## 3. Integrate and verify the agreed mechanic — pending

Replace a suitable temporary gameplay rule. Connect any explanation screen to the actual values used by the game. Test the numerical example and the complete player flow.

## 4. Prepare the final submission — pending

Check the final game against the rubric: introduction, visualization, rules and progression, calculus application, and mathematical significance. Regenerate the documentation and slides from that final version. Every group member should be able to explain their part and the selected mechanic.

A finished gameplay prototype alone does not complete the mathematical requirements.
